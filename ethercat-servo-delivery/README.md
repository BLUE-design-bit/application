# EtherCAT 伺服驱动器：从 PLC 客户路径到交付验收

初始研究日期：2026-09-11。当前工作簿：v2，功能与路径实测空白模板。

**目标：客户拿到交付包后，能够在约定的 PLC 平台上完成配置、运动、异常恢复和维护；现场出问题时，支持人员能够依靠证据快速定位。**

最初的品牌与PLC实测模板尚无实机结果；现已取得客户CiA402标准PDF及DFS-10A源码，用于下述静态审查。静态审查不代替产品兼容性或实机验收。

## 从这里开始

新版请使用 [EtherCAT 功能与路径实测 v2](outputs/01a08f03-8e5c-79e3-bb07-33816e14789f/EtherCAT_功能与路径实测_v2.xlsx)。106项功能、12类使用路径及三组PLC（汇川小型、汇川中大型、欧姆龙）已审定，M08已删除，来源见 [功能范围审定稿](functional-scope-review.md)。具体设备型号/版本、测试条件和实际路径组合待补。

“品牌勾选”包含318行（106项功能 × 3组PLC），右侧固定CDHD、台达、繁易、Elmo、KEBA（可选）五列，可筛选PLC与功能域。共1590个品牌格，初始均为未测试。

“路径与实测记录”预留1590条待展开记录及一条空白扩展行。实际设备组合、功能、入口组合及覆盖分支分别留证，记录测试人/岗位/日期、支持或受限等实际结果、证据和遗留问题。ST、梯形图、调试界面等适用路径不能互相代替；新增路径、版本或复测可追加表格记录。

“设备与测试条件”预留15个组合编号，登记具体设备、固件/ESI/PLC软件、基线资料及测试条件，并包含12类路径定义、适用边界和判据说明。编号仅为占位，不表示已选定设备或已确认兼容。

品牌勾选由工程师核对全部设备组合和适用路径/分支后填写；自动“记录齐全”只核对字段完整性，不代替人工判断覆盖是否完整或证据是否有效。“已勾选功能行数”与“实测记录齐全行数”分别统计。勾选不等于功能达标，资料确认、阻塞、不适用不算实测。

已检查逐行内容、公式、空白结果、记录扩展、下拉、日期、筛选和冻结窗格，查看三张表的渲染并独立读取导出文件复核。工作簿尚无实机结果，未在原生Excel应用中验证全部交互。

原 [109项Excel](outputs/01a08f03-8e5c-79e3-bb07-33816e14789f/EtherCAT_品牌实测_checklist.xlsx) 与 [旧版Markdown清单](acceptance-checklist.md) 保持原样，仅作历史参考。原研究和记录模板仍可提供资料依据，功能范围与新版工作簿以本次审定为准。

## DFS-10A 对客户 CiA402 标准的初审

[模块覆盖初审 Excel](outputs/01a08f03-8e5c-79e3-bb07-33816e14789f/DFS10A_CiA402_V3_模块覆盖初审.xlsx) 依据客户提供的 `CiA-402-2-version-3.0.0.pdf`，按第1–20章完整列出模块，并纳入文件末尾的2010年勘误。包含目录总览、12项重点差异/缺口、代码文件与行号依据三张表。

2026-09-16 静态初审：CSP/CSV/CST 核心控制通路已接入；PP、HM、IP、PV、PT、vl 未声明为标准模式。发现停机斜坡占位、60FE对象结构差异及CST反馈链缺口。可选模式或对象未支持不自动等于不符合；表中分别标识明确差异、静态缺口与待细审项目。本版未编译、烧录或进行实机符合性测试，不代表发布固件的认证结论。

生成脚本为 `scripts/build-cia402-audit.mjs`（使用共享运行时的 artifact-tool），独立只读复核脚本为 `scripts/verify-cia402-audit.py`。客户PDF和嵌套源码目录作为本地输入保留，不随本次审查产物提交。

## CiA402 第5章数据类型逐项核对

[数据类型逐项核对 Excel](outputs/01a08f03-8e5c-79e3-bb07-33816e14789f/DFS10A_CiA402_V3_数据类型逐项核对_v2.xlsx) 保留已认可的Sheet1及原有其余两张表，新增一张“数据类型逐项”。本次仅展开第5章，其他章节等形式确认后继续。

按客户PDF表1的11种类型、表2–4的13个记录字段逐项列出，共24项；保留标准页码、字段类型，并应用末尾2010年勘误的最高子索引命名修订。每项包含协议规定、当前判断、现在的实现、缺项/判定边界和代码依据，右侧黄色区域供人工核对和记录证据。

静态发现：7种基础类型已有处理；Time of day仅有类型编号；插补时间周期记录已有结构；插补数据配置及vl加减速记录未找到实际对象注册。类型处理存在不等于所有相关对象的运行行为符合，可选对象或未声明模式的缺失也不自动判不符合。

复现顺序：`scripts/extract-cia402-detail.py`提取客户PDF，`scripts/prepare-cia402-detail.py`准备第5章24项比较，共享Node运行时执行`scripts/build-cia402-detail.mjs`生成，再运行只读验证`scripts/verify-cia402-detail.py`。中间文件位于已忽略的`.cache/cia402-detail/`。已验证原三表的值和样式、24项来源清单、导出单元格逐项一致性和核对下拉；未编译、烧录或进行实机测试。

## 本轮研究内容

最新的客户标准核对见 [全章节逐项核对 v3](outputs/01a08f03-8e5c-79e3-bb07-33816e14789f/DFS10A_CiA402_V3_全章节逐项核对_v3.xlsx)。按2026-09-17确认的范围，第6–20章已接续展开，原四张表（含已认可的Sheet1和第5章明细）保持值、格式与人工核对栏不变。

新增对象属性3118行、行为与位定义611行、正文条款499行、勘误73行，以及来源覆盖索引。连续子项范围也展开到每个子索引：60A4:02–06、60C1:02–FE；其中可选子项未实现不自动判违规。共定位250张标准表、后续194个目录条款、72幅图；计数用于检查来源是否列入，不作为功能数、实现率或符合率。

源码判断分别给出已有声明/通路、明确差异、缺项与待核对的边界。尤其区分标准接口缺失和本地算法存在、共享对象存在和完整模式支持；图中箭头/曲线的细节仍应结合原PDF页核对。正文保留客户标准原文，受2010勘误影响的条款提示修订优先，相关表格替换已应用。未提供的CiA301、Part 3引用条款不作无依据的符合判定，也未进行编译、烧录或实机测试。

完整复现：先运行`scripts/extract-cia402-detail.py`，再运行`scripts/prepare-cia402-full.py`，执行`scripts/build-cia402-detail.mjs --full`，最后运行`scripts/verify-cia402-detail.py --full`。已检查四张已认可表的完整保留、逐格导出一致性、来源编号、连续子项、下拉框、错误单元格和新增表的渲染。客户PDF与嵌套驱动器源码继续作为本地输入，不随审查产物提交。

## 需要先补齐的输入

- 客户正在使用的 PLC CPU、运动/通信模块、固件、工程软件和运动库版本。
- 驱动器型号、硬件/固件版本、ESI、对象字典、已支持的工作模式与周期。
- 最近 1～3 个现场问题：客户做了什么、期望什么、实际发生什么、如何恢复。
- 电机/编码器、水平或垂直负载、制动器、原点与限位接线，以及客户性能指标。

这些信息不齐时仍可继续协议与路径研究，但相关兼容性和数值验收应保持“待确认/阻塞”。第一轮实机应优先覆盖真实出问题的客户组合。
