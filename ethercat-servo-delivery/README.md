# EtherCAT 伺服驱动器：从 PLC 客户路径到交付验收

研究日期：2026-09-11。版本：v0.1，调研与验收设计稿。

**目标：客户拿到交付包后，能够在约定的 PLC 平台上完成配置、运动、异常恢复和维护；现场出问题时，支持人员能够依靠证据快速定位。**

目前未取得本产品的 ESI、对象字典、固件、PLC 工程或实机测试结果。本文档中的检查项均未执行，不能作为产品兼容性或验收通过的声明。

## 从这里开始

1. 阅读 [研究结论与客户路径](research/01-customer-journey.md)，确定交付边界。
2. 填写 [产品与客户基线](templates/01-product-customer-baseline.md)，先锁定真实客户的 PLC、版本、模式与机械参数。
3. 按 [验收 checklist](acceptance-checklist.md) 执行，为每项记录结果和证据；需要展开步骤时使用 [单项验收记录](templates/02-test-record.md)。
4. 把客户故障填入 [现场问题采集与排查](templates/03-field-support.md)，复现后加入回归用例。

## 需要先补齐的输入

- 客户正在使用的 PLC CPU、运动/通信模块、固件、工程软件和运动库版本。
- 驱动器型号、硬件/固件版本、ESI、对象字典、已支持的工作模式与周期。
- 最近 1～3 个现场问题：客户做了什么、期望什么、实际发生什么、如何恢复。
- 电机/编码器、水平或垂直负载、制动器、原点与限位接线，以及客户性能指标。

这些信息不齐时仍可继续协议与路径研究，但相关兼容性和数值验收应保持“待确认/阻塞”。第一轮实机应优先覆盖真实出问题的客户组合。
