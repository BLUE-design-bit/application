# 现场问题采集与排查

目标：客户只说“轴不能动”时，能够定位到工程配置、总线、驱动状态、PLC 运动层或机械条件，并给出可复现的下一步。

## 客户填写的最小问题单

| 问题 | 记录 |
| --- | --- |
| 在哪台设备、哪根轴、哪次软件/固件变更后出现 | 待填写 |
| PLC/模块/驱动/电机型号和全部版本 | 待填写 |
| 客户最后做了什么；期望和实际结果分别是什么 | 待填写 |
| 上电即出现、偶发、还是可稳定复现；发生频率 | 待填写 |
| 发生时静止/运动/回零/停机/复位/升级 | 待填写 |
| 最先出现的报警、之后的报警、时间戳 | 待填写 |
| 总线状态、PLC 功能块错误、驱动报警各是什么 | 待填写 |

## 分层排查卡

| 现象 | 先采集 | 定位顺序 | 不应直接得出的结论 |
| --- | --- | --- | --- |
| 找不到从站 / 设备型号不符 | 拓扑、链路、设备身份、ESI版本 | 供电与端口 → 主站能力 → 扫描身份 → 设备库匹配 | 不能仅靠换 ESI 就认定固件兼容 |
| 卡在 PREOP / SAFEOP | AL 状态码、启动 SDO、PDO 与 DC 参数 | 首个失败转换 → SDO abort → PDO长度 → 同步周期/相位 | 不能一律关闭 watchdog 或降低检查严格度 |
| OP 但不能使能 | 0x6040/0x6041、电源/STO/限位、PLC轴错误 | 通信有效 → CiA402状态 → 硬件条件 → 轴绑定/许可 | OP 不代表功率级已使能 |
| 使能但不动 / 一动就跳 | 模式命令与显示、目标/实际值、单位、控制权 | 模式握手 → 当前目标 → PDO偏移 → 单位方向 → 轴规划 | 驱动能用厂家软件点动不代表 PLC 路径正确 |
| 动作执行后 Busy 不结束 | 功能块输入输出、轴状态、模式位、到位窗口 | 调用周期/触发 → 命令冲突 → 完成判据 → 反馈与报警 | 不应把永远等待当作正常延迟 |
| 偶发抖动/跟随误差 | 任务抖动、WKC、同步状态、目标连续性、转矩 | 时间相关性 → 总线/调度 → 限幅 → 负载/调谐 | 不凭症状先归因于 PID |
| 复位后立即再报 / 自动再跑 | 首发原因、Fault reset沿、Enable/Execute保持状态 | 原因是否解除 → 驱动复位 → 轴复位 → 目标和命令重建 | MC_Reset 完成不代表所有层已经恢复 |
| 重启后参数丢失 / 换机行为变了 | 参数差异、启动写入、固件/ESI身份、回零状态 | 存储 → PLC覆盖 → 版本迁移 → 绝对位置基准 | 不能只备份厂家调试软件参数 |

此表为工程排查建议，诊断对象与行为以本产品和实际 PLC 文档为准。

出现异常跳动、失转矩或垂直负载风险时，先按设备停止流程结束运动；复现转移到具备约束与独立停止手段的台架，不能在生产设备上反复试错。

## 支持演练验收

让未参与驱动开发的应用工程师仅凭交付包完成三个任务：从空工程使轴运动、定位一个预设配置错误、完成一次换机恢复。记录耗时、追问次数、缺失资料和误判。演练不依赖开发者现场解释隐含步骤；不能完成的步骤应补进交付包后再验。
