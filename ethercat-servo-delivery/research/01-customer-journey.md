# 调研结论：按客户路径定义完整交付

日期：2026-09-11。适用假设：产品拟通过 EtherCAT 的 CoE/CiA402 接入 PLC；本产品的实际能力尚待确认。

## 1. 这次要补的交付缺口

用户已经指出的事实：团队实现了 EtherCAT 功能，但客户在 PLC 中采用了此前没有覆盖的用法，现场出现问题后团队难以及时处理。

据此提出的工程判断：验收单位应从“驱动支持了哪个对象/模式”扩大为“客户在某个已冻结的平台组合上，能否完成一个完整操作并处理失败”。交付至少包含设备、ESI/参数、PLC 示例工程、操作说明、诊断与恢复办法以及对应证据。

不能通过有限测试证明覆盖所有客户的任意用法。可执行的目标是：列清能力边界，覆盖承诺范围内的全部关键路径和高风险组合，保留未覆盖项，并持续把现场问题转为回归用例。

## 3. 客户会经过的路径

| 阶段 | 客户实际动作或分支 | 经常被遗漏的分支 | 应交付的材料 / 验收入口 |
| --- | --- | --- | --- |
| 选型 | 看规格、确认 PLC 能否带该驱动 | PLC 有网口但无合适的 EtherCAT 主站；只有 I/O 通信，运动轴功能不具备 | 精确平台矩阵、模式与限制；BAS、PLC |
| 获取资料 | 下载 ESI、手册、固件、示例 | 同名文件版本不同；工程使用旧设备库；缺少许可证/库 | 带版本和校验值的发布包；BAS、ESI |
| 接线与建站 | 在线扫描或离线添加从站 | IN/OUT、接地屏蔽、拓扑和上电顺序不同；多台同型设备识别错误 | 接线图、身份与拓扑核对方法；ESI、COM |
| 配置轴 | 导入 PDO、Startup SDO、DC，关联 PLC 运动轴 | 设备节点出现却没有运动轴；绑定错轴；自动与手工映射不同 | 每平台建轴步骤和可编译工程；PLC、COM |
| 首次使能 | 电源就绪、MC_Power、厂家软件点动 | STO/制动器未满足；控制字被双写；旧目标造成突跳 | 使能时序、控制权说明、无意运动检查；DRV |
| 设置坐标 | 电子齿轮、单位、方向、零点 | PLC 和驱动重复缩放；绝对编码器坐标无效；溢出/模数跨界 | 单位公式、机械例子、坐标有效性规则；UNT |
| 回零 | PLC 规划回零或驱动 HM | 原点已触发、找不到原点、中断、限位、索引、重新上电 | 按方法分支的回零流程；HOM |
| 正常生产 | 点动、定位、速度、转矩、连续轨迹 | Execute 保持/重复沿、命令中断、排队、方向切换、运行改目标 | 各功能块正常/异常示例与 Trace；MOT |
| 停止与再起动 | Halt、Stop、撤使能、Quick stop | 各种停止的作用不同；旧命令仍保持；恢复后意外续跑 | 停止策略表、重启条件；MOT、REC |
| 系统异常 | PLC STOP/下载、断链、失步、主电掉电 | 控制电仍在；总线恢复但轴未恢复；只有重启才可清除 | 故障响应时间与恢复步骤；REC |
| 扩展应用 | 多轴、齿轮/凸轮、锁存、后台参数访问 | 总线通但高级对象缺失；CPU负载/轴数增加后失败 | 已验证配置、限制和压力报告；ADV |
| 维护变更 | 备份、复位默认、升级、替换、项目迁移 | 参数被 PLC 覆盖；新旧 Revision 不匹配；回零基准丢失 | 版本迁移说明、恢复包；LIF |
| 售后交接 | 客户报错、应用工程师排查 | 只截最终报警；没有工程、首发错误、波形或复现步骤 | 一页排查卡、采集包、回归记录；SUP |

## 4. 用四层状态解释“不能动”

1. **网络层**：链路存在吗？设备身份正确吗？ESM、AL 状态、过程数据有效性、同步是否符合要求？
2. **驱动层**：CiA402 状态、模式反馈、电源/STO/限位/报警、目标与实际值分别是什么？
3. **PLC 运动层**：轴是否正确关联？功能块是否持续按平台要求调用？命令被谁接管？轴为何处于错误或停止状态？
4. **机械与应用层**：单位、方向、制动器、负载、原点和限位是否吻合？软件显示完成是否对应实际动作？

前三层状态需要在同一时间线上关联；单独截一个“OP”或“Error”不足以定位。

## 5. 如何在有限工作量内形成覆盖

先补“真实问题客户”的路径，再建立参考平台。TwinCAT、CODESYS 和 Omron 在本轮作为研究样本，不能据此宣称已适配，也不建议在客户平台未知时先购买整套设备。

最重要的覆盖维度是：主站/库版本、驱动/ESI版本、模式、周期、PDO集合、轴数、负载和编码器、上电/恢复状态。优先做：

- 每个实际支持组合的端到端主路径。
- 各模式/周期/PDO/编码器的边界与错误输入。
- 运动中断链、失电、复位、控制权接管等高风险组合。
- 新增平台与固件变更的差异测试；其余低风险组合使用有记录的抽样。

先填写 [基线与兼容性矩阵](../templates/01-product-customer-baseline.md)，再勾 [checklist](../acceptance-checklist.md)。没有可观测判据、冻结阈值或证据的检查项不能标记通过。

## 6. 第一轮建议执行顺序

1. 重现现有客户问题，取得 ESI、PLC 工程和固件基线，形成失败用例。
2. 从空工程建站、建轴，执行使能、正反点动和单位校验。
3. 验证实际使用的定位/回零路径，以及 Halt、Stop、复位的完整循环。
4. 验证 PLC STOP/RUN、控制电与主电顺序、通信中断恢复和目标连续性。
5. 断电保存、换机恢复，交给另一名应用工程师按包复现。
6. 扩展到客户承诺的其余功能、轴数、周期与长期运行。

产品负责人冻结“承诺什么”；固件工程师解释对象与状态；PLC 应用工程师维护每个平台的工程；测试人员保留证据；支持人员以交付包完成独立演练。尚未分配人员时，在基线保留角色即可。
