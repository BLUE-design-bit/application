## 全局要求：同时覆盖用户使用路径

用户新增要求：用户使用驱动器 EtherCAT 功能的路径都要遍历，明确包括导入 XML、ST、梯形图和调试界面。功能覆盖与入口覆盖同时成立；条目仍是需要验证的能力和行为，不改写成逐步操作教程。

后续 Excel 按“品牌 + 驱动/PLC版本组合 + 功能ID + 使用路径”保存独立记录。一个品牌功能格仅在全部适用路径和分支完成后汇总勾选，不能用某一个入口的成功代替其他入口。实际平台不具备的入口单独记录不适用及依据，缺软件/硬件或尚未测试不能记为不适用。

路径细分草案如下，具体清单后续单独交用户审定：

| 路径类型 | 应记录的覆盖分支 |
| --- | --- |
| XML / ESI 与工程配置 | 正式XML导入、版本更新；离线建站、在线扫描；正式设备描述与在线描述回退（如有） |
| ST 程序 | 客户实际使用的运动功能块、参数访问功能块及程序逻辑 |
| 梯形图程序 | 对应功能的梯形图调用及程序逻辑，单独留证，不沿用ST的结果 |
| PLC 调试界面 | 轴调试、点动/定位、参数在线读写、状态与报警查看等实际可用入口 |
| 控制方式 | 厂商运动库/原生轴控制与直接读写PDO、手写CiA402控制分别记录；与编程语言组合覆盖 |
| 参数下发方式 | 启动参数自动写入、程序主动SDO访问、在线对象浏览器读写及其并存/覆盖行为 |
| 厂家调试工具 | 明确实际经过EtherCAT、EoE或独立USB/串口/其他接口；独立接口成功不能代替EtherCAT路径 |
| 客户应用触发 | 适用的HMI操作、自动程序触发、多个入口并存与控制权交接 |

XML导入属于配置路径，ST/梯形图属于程序表达入口，PLC调试界面属于操作入口；它们不是同一维度的互斥选项。例如“导入ESI + ST + 运动库”与“导入ESI + 梯形图 + 运动库”应能分别追溯。用户要求覆盖全部适用路径，不在未经确认的情况下以抽样代替。

### D06—D09 场景解释与资料依据

- D06：把同一对象下的多个子项作为一组访问。例如主站初始化时整组下发配置，而不是逐子项访问。它描述“访问哪些子项”，并不保证数据都在一个网络帧里完成。[Beckhoff CoE说明](https://infosys.beckhoff.com/content/1033/tc3_io_intro/1357984011.html)、[CODESYS启动参数的Full access](https://content.helpme-codesys.com/en/CODESYS%20EtherCAT/_ecat_edt_module_start_parameter.html)。
- D07：某个对象的数据超过邮箱可承载长度时，分多段传完。工程场景举例是设备确实提供的较长字符串、大数组或厂商数据块；它们是否存在、是否足够大须查实际对象字典。不能用FoE固件文件传输代替SDO分段。[ETG.1500 §5.7.2及5.7.3](https://www.ethercat.org/download/documents/ETG1500_V1i0i2_D_R_MasterClasses.pdf)，本次获取官方搜索索引中的相关段落，PDF直接抓取返回403。
- D08：工程场景举例是生产运动继续运行时，由PLC/HMI读取诊断数据，或用在线工具调整明确允许在线修改的参数。需分别了解可读/可写范围与访问负载下的行为，不能把“未使能时SDO读写成功”当作运行中也可用。[Beckhoff CoE Online](https://infosys.beckhoff.com/content/1033/tc3_io_intro/1446522251.html)提供在线对象读写和自动更新入口；运动中负载测试为本项目工程建议。
- D09：PLC使用PDO反馈，同时调试界面通过SDO查看同一对象时，需要知道数字的含义是否一致、是否需换算。Kollmorgen AKD官方资料确实列出某些配置下PDO与SDO位置缩放不同。该例只证明此类差异存在，不代表五个参考品牌均如此。动态量应考虑采样时刻，不能直接比两个不同时刻的数值。[Kollmorgen AKD位置缩放](https://www.kollmorgen.com/en-us/developer-network/position-scaling-akd-drive-ethercat-communication)。

以上资料于本轮答疑核查；应用举例与验收建议不构成对参考品牌已支持功能的声明。

| P03 | 参数保存与掉电保持 | 临时值与永久值的区别、保存入口、保存完成/失败反馈，以及重启和断电后的实际保持范围 |
| P04 | 启动参数与现有参数的覆盖 | PLC启动参数、驱动已保存参数、在线修改值和PDO周期写入并存时，实际采用哪一个值、何时被覆盖及如何追溯来源 |
| P05 | 启动参数下发异常 | 参数依赖/顺序、下发状态、超时、拒写或部分失败时的提示、建站结果及重试后的配置完整性 |
| P06 | 参数备份与恢复 | PLC或厂家工具可导出/恢复的范围、遗漏项、差异比较，以及恢复后的实际配置与原机是否一致；记录实际传输接口 |
| P07 | 恢复默认设置 | 支持整机/分组恢复哪些默认值，对通信、轴配置及重新接入的影响；厂家工具与EtherCAT入口分别记录 |
| P08 | 设备与版本匹配 | 型号、产品标识、硬件/固件版本与ESI、PLC工程的匹配检查；不匹配时能否识别、提示并定位差异 |
| P09 | 更换驱动与配置迁移 | 同型号同版本及厂家声明兼容的版本之间，更换后哪些配置可自动恢复、哪些需人工补齐；节点身份、轴对应和机器专用参数是否正确 |
| P10 | 固件升级与升级后兼容性 | 是否支持经EtherCAT升级（如FoE），实际限制、失败/中断恢复能力，以及升级后的参数、对象字典、PDO和原PLC工程兼容性 |

P01不要求所有整定功能都能通过EtherCAT完成，只要求明确交付时客户能走的真实路径。P08的版本匹配与后续XML/ESI入口覆盖关联。P09不默认跨型号或任意版本可迁移；不可复制的设备校准值及机器专用参数需明确边界。P10按实际升级能力确定适用性，独立USB等接口升级不能记为EtherCAT升级成功；仅提供FoE传输也不能证明支持固件升级。

## 8. 报警、诊断与现场排障：已确认

用户决定：A01—A09全部保留。关注客户通过PLC及其他实际入口能够获得的诊断信息和故障证据；与S组、N组已覆盖异常关联复用，分别记录故障本身的行为和诊断可见性。

| 编号 | 功能 | 覆盖范围 |
| --- | --- | --- |
| A01 | 当前故障与警告 | 可读取哪些故障/警告、严重程度及详细原因；仅预警、限制运行与停机故障如何区分，当前状态是否及时更新 |
| A02 | PLC与驱动报警对应 | PLC轴错误、EtherCAT通信错误、驱动故障码与厂家工具显示如何对应；能否从PLC获得原始原因而非只有通用错误 |
| A03 | 短时与连续报警事件 | 实际提供的事件通知/主动上报或轮询机制，短时出现后消失、连续发生及重复故障能否被PLC捕获；延迟、去重和丢失边界 |
| A04 | 故障历史与保持 | 历史容量、先后顺序、时间信息及故障现场值；清故障、重启、掉电后的保留情况及清除入口 |
| A05 | 多故障与最初原因 | 多个故障同时或先后发生时，首个原因、后续连锁故障和仍未消除的原因能否区分，显示/上报优先级如何处理 |
| A06 | 无报警但不动作的诊断 | 未使能、模式未就绪、限位、指令未接受、控制权冲突等场景，能否看到具体阻止原因及命令接受/执行状态 |
| A07 | 运行状态与诊断量 | 实际开放的跟随误差、负载/转矩、母线电压、温度、I/O及通信诊断量的访问入口、单位、刷新速度和有效性；区分主站统计与驱动提供的数据 |
| A08 | 波形与故障现场捕获 | PLC采样和驱动内部记录各能捕获哪些量、采样周期/长度、触发及故障前后数据；能否经EtherCAT取得，断线后哪些证据仍可保留 |
| A09 | 诊断资料导出与追溯 | 报警历史、波形、参数快照、通信状态及设备/软件版本能否导出并关联到同一故障；明确需从哪些入口分别取得及时间能否对齐 |

A03不预设设备支持某种主动上报机制，实际只有轮询时也需记录可捕获范围。A06各场景按实际报警行为归类，不假定所有驱动均不报警。A07/A08不要求所有监测量或内部记录功能必备，PLC周期采样与驱动内部高速采样分别记录，不能混作相同性能。厂家工具通过独立接口获得的信息不代表PLC可通过EtherCAT获得；故障时的旧缓存数据需标明有效性。A09可关联多份导出资料，不强制设备提供一键诊断包。

## 9. PLC接入与用户使用路径：待确认

以下12项为路径范围审定候选，不构成已批准的具体分支。全局要求中的全部适用路径覆盖仍有效。本组描述各入口应跑通的能力与行为，不编写点击、编程或配置教程；功能测试结果按实际使用的路径组合关联。

| 编号 | 候选路径 | 覆盖范围 |
| --- | --- | --- |
| E01 | XML / ESI导入与更新 | 正式文件能否导入、正确显示型号/版本/PDO/同步等信息；旧新版本并存、替换和工程重新打开后的选择及解析结果 |
| E02 | 离线建站与在线扫描 | 离线选型建站、在线扫描识别、扫描结果与已有工程匹配；缺少正式ESI时平台实际提供的识别/回退能力及限制 |
| E03 | PLC轴创建与驱动绑定 | 平台原生驱动适配、通用CiA402轴、厂家模板等实际入口，轴与设备/PDO绑定、默认配置及反馈是否正确 |
| E04 | 运动库与厂家功能块 | PLC标准运动库、厂家专用库及示例工程实际可调用哪些运动/参数/诊断功能，命令接受、执行、完成、中断和错误反馈是否可用 |
| E05 | 直接PDO / 对象控制 | 不经运动库时，通过程序直接处理控制字、状态字、模式和目标/反馈，能否完成适用功能并处理异常；明确与轴库并存限制 |
| E06 | ST程序 | 经ST实际调用运动、参数访问与诊断功能；触发、连续更新、中断及复位的实际表现，不能沿用其他语言的测试结果 |
| E07 | 梯形图程序 | 经梯形图实际调用对应功能；触点保持、单次触发、重复触发及多功能块调用时的执行/反馈表现，独立留证 |
| E08 | 其他可用编程入口 | 平台实际提供的FBD/CFC、SFC等图形或顺序编程入口，适用功能的调用及动作衔接；与所调用的ST/梯形图等程序组合记录 |
| E09 | PLC调试与在线监视界面 | 轴调试、点动/定位、使能/复位、在线变量监视/写入等实际入口可完成哪些功能，显示是否正确及与程序控制的交接 |
| E10 | 参数访问入口 | 启动参数列表、ST/梯形图中的SDO功能块、在线对象浏览器等分别验证读写/反馈；入口并存和覆盖结果关联D组、P组 |
| E11 | 厂家调试软件接入 | 软件直连、经主站转接、EoE等实际可用路径的连接、配置、监视及与PLC并存能力；记录实际接口和主站依赖 |
| E12 | HMI与自动运行入口 | HMI按钮/配方、自动程序触发适用运动及参数功能，状态/错误能否传回，手动与自动切换及入口冲突如何处理 |

这些路径不是12选1：例如“正式ESI导入 + 通用CiA402轴 + PLC运动库 + ST”和相应梯形图组合分别留证。最终Excel按品牌、驱动/PLC/软件版本、功能ID和路径组合记录；本组用于维护入口覆盖矩阵，不将79项已确认功能机械地乘以12。对每项功能列出全部实际适用组合，缺设备或软件记为阻塞/未测试，入口不存在才有依据地记为不适用。平台/型号/版本的具体清单仍需单独确定，不能据此声称覆盖所有市售PLC。E04/E08/E12中的PLC应用能力与驱动本身能力分别归属；E11不预设每台驱动均支持EoE，独立接口成功不代替EtherCAT成功。
